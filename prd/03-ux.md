# 03. 投入と閲覧

> **実装済み**（Phase 1-5 / 1-6）: 投入口（ページへのペースト / 貼り付けボタン / D&D /
> ファイル選択）と判別・即保存（§1）/ 新しい順の一覧とプレビュー・折りたたみ（§2）/
> クリックでコピー・ダウンロード（§3）/ 確認付きの削除（§4）/ レスポンシブ（§5）。

## 1. 投入

**テキストの入力欄を作らない。** 文字を打ち込む場所は用意せず、**貼られたものが増えていくだけ**にする。
「何かを書く道具」ではなく「受け渡しの中継点」であることを、UI の形で表す。

| 経路 | 操作 | 端末 |
|---|---|---|
| **ページへのペースト** | 画面上で `⌘`/`Ctrl` + `V`（どこにもフォーカスせずに） | Windows / MacBook |
| **貼り付けボタン** | 1タップ → OS の許可 → クリップボードを読む | **iPhone**（§1.3） |
| ドラッグ&ドロップ | 画像ファイルを画面に落とす | Windows / MacBook |
| ファイル選択 | 写真アプリ / ファイルから選ぶ | 全端末（画像のみ） |

### 1.1 判別と保存

貼られた中身を見て `kind` を決める。**人間に選ばせない。**

- ペーストは `ClipboardEvent.clipboardData`、D&D は `DataTransfer` を見て、
  **ファイルが含まれていれば `image`、なければ `text`** として扱う。
- **クライアント側で申告 MIME を見て allowlist 外と判断し、送る前に弾かない**（**3つの経路すべて**。
  貼り付けボタン（§1.3）も例外ではない）。
  `File.type` は申告値にすぎず、**正しい PNG や JPEG でも空文字や `application/octet-stream`
  になることがある**。ここで弾くと、正しい画像が §1.2 のシグネチャ検証に到達しないまま
  拒否されてしまう。形式の判定は**サーバー1箇所に集約する**。
- **すべて即保存する。** 確認ダイアログも保存ボタンも確定操作も挟まない。
  テキストも画像も、**貼られた瞬間に1エントリとして一覧の先頭に増える**。
- 入力欄が無いため「入力途中の状態」が存在せず、保存タイミングの判断が要らない。

### 1.2 受け付ける形式

**画像は PNG / JPEG / GIF / WebP のみ受け付ける。**

- **SVG は受け付けない。** SVG は能動コンテンツ（スクリプトを含みうる）であり、
  private データと同一オリジンから inline 配信すると、開いた瞬間にアプリのオリジンで実行され、
  認証済み API を操作されうる（stored XSS）。**自分で貼ったものだけとは限らない**
  （他人からもらった画像を中継する用途がある）ため、形式で弾く。
- **クライアントが申告した MIME を信用しない。** サーバーが実体の先頭バイト（ファイルシグネチャ）から
  形式を判定し、allowlist 外なら保存しない（[02](./02-data-model.md) §4）。
- テキストは形式を問わない（プレーン文字列として保存する）。

### 1.3 iPhone での経路

**iOS Safari はページに `paste` イベントを配らない。** `input` / `contenteditable` にフォーカスが
ある時しか発火せず、「ページに向かって貼り付ける」操作自体が OS に存在しない。
**ペースト一本では iPhone から投入できない。**

そこで **「貼り付け」ボタン**を置き、押されたら `navigator.clipboard.read()` でクリップボードを読む。

- `clipboard.read()` は**ユーザー操作の中でのみ**許可され、OS の貼り付け許可 UI が出る（iOS 13.4+）。
- **これは入力欄ではない**ので、「打ち込む場所を作らない」という方針と矛盾しない。
- 読み取りが拒否・失敗した場合は、**その旨を表示して「画像を選ぶ」に誘導する**。
  ⚠ **自動でファイル選択を開くことはできない。** 権限 UI を経た後の時点では、クリック由来の
  transient user activation が切れており、iOS Safari はファイル選択を無視する。
  自動で開こうとすると「押しても何も起きない」状態になるので、**利用者の次のタップに委ねる**。
- ボタンはデスクトップでも常に見える位置に置く（iPhone だけの特別扱いをしない）。デスクトップでは
  `⌘`/`Ctrl` + `V` の方が速いが、経路を分岐させない。

### 1.4 エラー

いずれも**保存せず**、理由を表示する。

- 画像が 20MB 超過（[02](./02-data-model.md) §5）→ 「20MB を超えています」
- テキストが上限超過（[02](./02-data-model.md) §5）→ 「テキストが大きすぎます」
- allowlist 外の形式（SVG・PDF・zip 等）→ 「PNG / JPEG / GIF / WebP のみ扱えます」
- 保存失敗 → 投入した内容を**画面から消さない**。貼り直しを強いない。

**投入は同時に走りうる**（ページへのペーストと D&D は、保存中でも新しい投入を始められる）。
そのため失敗は**投入1件ごとに保持し、それぞれを個別に再試行できる**ようにする。
まとめて1つの状態にすると、**同時に走った別の投入の成功が、失敗した内容と再試行導線を消す**。

## 2. 一覧

**新しい順の時系列のみ。** 検索・タグ・絞り込みは持たない（[05](./05-roadmap.md) §未実装）。

- **50件ずつ**読み込む。並び順は `id`（ULID）の降順単独で、ページングのカーソルも `id`
  （[02](./02-data-model.md) §2）。
- 受け渡し用途では目的のものは大抵一番上にあるため、**最上部が最新**であることを最優先にする。
- 各エントリに表示するもの: 中身のプレビュー、作成時刻、操作。

### プレビュー

| 種別 | 表示 |
|---|---|
| テキスト | **プレーン表示**（等幅）。Markdown としてレンダリングはしない。長いものは折りたたみ、展開できる |
| 画像 | **原寸を CSS で縮小**して表示 |
| 壊れているもの | **「壊れています。削除してください」と明示する**（下記） |

**壊れた項目を黙って隠さない。** 削除の途中失敗で実体を失った行は、一覧に残して
「実体が見つかりません」と表示する（[02](./02-data-model.md) §3.2）。コピーとダウンロードの
導線も出さない（押しても失敗するため）。**壊れた画像アイコンだけを出して放置しない。**

**Markdown をレンダリングしない理由**: 貼るのは受け渡し対象の文字列そのものであり、
整形されると「元の文字列が何だったか」が分からなくなる。**貼ったものがそのまま見えることを優先する**。

**サムネイルを生成しない理由**: 実装と失敗時のフォールバックを MVP に持ち込まないため
（[05](./05-roadmap.md) §未実装）。回線で重いと感じたら後から足す。

## 3. 取り出し

別端末で受け取るための操作。**カード本体をクリック（タップ）したらクリップボードにコピーされる。**
コピーボタンを探させない。

| 種別 | クリック時の挙動 |
|---|---|
| テキスト | `navigator.clipboard.writeText()` で文字列をコピー |
| 画像 | `navigator.clipboard.write()` で画像をコピー。**未対応・失敗時はダウンロードにフォールバック** |

- コピーできたことが分かるフィードバックを必ず出す（何も起きないと成否が分からないため）。
- **ダウンロードボタンは別に置く**（`Content-Disposition: attachment`）。iPhone では
  クリップボードより写真アプリへ保存したい場面があるため、コピーだけに寄せない。
- 画像の拡大表示もカード本体クリックとは別の操作にする（クリック＝コピーと衝突させない）。

## 4. 削除

- **確認ダイアログを挟む。** 投入は確認なしで即座に通す代わりに、**破壊操作だけは守る**。
- 削除するとエントリと画像の実体の両方が消える（[02](./02-data-model.md) §3）。復元はできない。

## 5. レスポンシブ

Windows / MacBook / iPhone のいずれからも使う。daisyUI + Tailwind のユーティリティで
**同じコンポーネントを幅で出し分ける**（別画面を作らない）。
