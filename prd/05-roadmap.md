## 未実装・やらないこと

**いずれも「後から足せる形にしておく」ことだけを設計上の要件とし、MVP では作らない。**

| 項目 | 作らない理由 | 阻害しないための担保 |
|---|---|---|
| 検索 | 受け渡し用途では目的のものは最上部にある。溜まって困ってから足す | 一覧 API がページング前提なので、条件を足せる |
| タグ・タイトル | 入力の手数が増え、即保存（[03](./03-ux.md) §1）と相性が悪い | `clips` に列を足すだけで済む |
| 自動失効 | 「消えて困った」事故を原理的に起こさないため | 期限列を足せば実装できる |
| **ログイン試行のレート制限**（issue #3） | **本番も含め、前段プロキシ（認証付き）の内側でしか動かさない**（[06](./06-deployment.md) §5）。自前で正しく作ると分散ロックの設計になる（[04](./04-auth-and-privacy.md) §2） | 実装するときは**自作せず既存実装に寄せる**（`better-auth` 内蔵 / `hono-rate-limiter` 等）。**前段の無い場所へ移す前に必ず入れる** |
| サムネイル生成 | 画像処理依存と生成失敗時のフォールバック設計を持ち込まないため | 配信が `/api/clips/:id/blob` に一本化されているので、派生を足せる |
| 任意ファイル | 「貼ってプレビューできる」性質から外れる | `kind` が enum なので値を足せる |
| **他者への人間向け共有** | 受け手は LLM であり、**無認証で開ける画面を増やしても得るものがない**（[03](./03-ux.md) §6） | 共有トークンの仕組み（[04](./04-auth-and-privacy.md) §3.1）はそのまま使える。返す形を足すだけで済む |
| **共有中のものの一覧・管理画面** | 現実に起きる事故は「渡した直後に気づく」で、発行直後の失効と 10 分の期限で足りる（[03](./03-ux.md) §6） | **`shares` の行が残っているので、画面を作れば答えられる**。署名方式ならこれが原理的に不可能だった（[`_grilling/decisions.md`](./_grilling/decisions.md)） |

## 確定事項

grill による決定（詳細は [`_grilling/decisions.md`](./_grilling/decisions.md)）。**これらは「まだ決めていないこと」
ではなく、意図して選んだ結論である。**

- **貼ったものは自動で消さない。** 消すのは自分の意思による削除だけ。
- **扱うのはテキストと画像のみ。**
- **1エントリはテキストか画像のどちらか一方。** 同居させない。
- **認証はアプリ側の cookie セッション。** 前段プロキシに依存しない。
- **画像の実体は SeaweedFS、メタデータは MySQL。**
- **一覧は新しい順の時系列のみ。**
- **サムネイルを作らず、原寸を CSS で縮小して表示する。**
- **パッケージは `web` と `server` の2つ。** `shared` も `database` も作らない。
- **共有は clip ID とは独立したトークンで行う。** ULID を共有 URL の防壁にしない
  （[02](./02-data-model.md) §2 / [04](./04-auth-and-privacy.md) §3.1）。
- **共有は `/s/` 配下に隔離する。** 既存の認証必須パスに無認証の抜け道を作らない。
- **共有トークンの状態は MySQL に置く。** Redis / Valkey は入れない（[02](./02-data-model.md) §6）。
